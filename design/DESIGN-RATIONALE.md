# 设计原理

版本：2026-09-24 / checkpoint 1

## 1. 目标用户与首屏问题

| 角色 | 典型查询 | 进站后 5 秒内要得到的答案 |
|---|---|---|
| 工具用户 | bip39 generator / validator / checksum | 工具就在这里；输入会不会离开设备；真实短语该去哪 |
| 学习者 | what is bip39 / bip39 passphrase | 一句话定义 + 一张图；可以动手试 |
| 开发者 | bip39 word list / test vectors | 数据来源、版本、哈希、下载格式 |

所有页面首屏必须能回答 CLAUDE-BRIEF 的五个问题：能做什么、哪些适合在线、何时下载离线版、输入是否离开设备、证据在哪里。

## 2. 设计原则

1. **任务先于叙事**：工具页 H1 下一行是一句承诺，再下面直接是工具。说明文字、原理、FAQ 全部在工具之后。
2. **证据代替口号**：不使用盾牌、锁头装饰图。用可核对的东西表达安全：版本号、SHA-256、源码链接、"Network requests during computation: 0" 这类可验证陈述，并告诉用户怎么自己验证。
3. **秘密区域与普通内容视觉分层**：任何可以接收助记词、entropy、passphrase 的输入框都放在统一的 "Secret field" 容器里（见设计系统 §4.3）。它有固定的外观和一条常驻说明，用户一眼就能分辨"这里是敏感输入"。
4. **提示常驻而克制**：不使用阻断式弹窗。每个秘密输入区上方有一行 inline notice；页面右上/工具顶部有一个 Online / Offline 模式徽标。
5. **把结构可视化**：entropy bits、checksum bits、11-bit 分组、word index 用等宽网格直接画出来，用户看得到"为什么 12 个词里最后一个不是随便选的"。
6. **测试数据显式标注**：所有示例值旁标 `TEST VECTOR` 或 `DEMO` 标签，数据取自官方 BIP39 测试向量（trezor/python-mnemonic vectors.json）。
7. **诚实的空缺**：尚不存在的证据（审计、可复现构建、签名）显示 `Not yet available` 而不是隐藏或伪造。

## 3. 搜索意图如何影响布局

| 意图类型 | 页面 | 首屏布局 |
|---|---|---|
| 执行型（generate/validate/convert） | Generator、Validator、Converter | H1 + 一句话 + 工具卡片占满首屏；右栏（桌面）或工具下方（移动）放"Online vs Offline"简卡 |
| 查询型（word list） | Word List | H1 + 搜索框 + 词表网格；下载按钮与来源哈希在搜索框同一行 |
| 理解+计算型（checksum、passphrase） | Checksum、Passphrase | H1 + 40 词定义 + 分步交互图，交互本身就是解释 |
| 学习型（what is bip39） | What Is BIP39 | 定义段落 + Entropy → Mnemonic → Seed 流程图，随后长文 |
| 下载/信任型（offline） | Offline | 版本、大小、SHA-256、下载按钮同屏；验证步骤紧随其后 |
| 导航型（bip39） | 首页 | 定义 + 四个任务入口 + 离线提示，不嵌入完整工具 |

## 4. 视觉方向

- 感受：技术文档 + 精密仪器面板。参考语气接近标准文档、开源项目主页，而不是交易所。
- 默认浅色，提供深色模式（跟随系统，可手动切换，偏好存 localStorage，只存主题不存数据）。
- 单一冷色强调色（深青蓝）用于操作；琥珀色专用于"敏感/注意"；绿色和红色只用于校验结果。
- 数据一律等宽字体，按 11-bit / 4-bit 分组显示，长串可换行不溢出。
- 不使用渐变背景、玻璃拟态、金色、币价与图表意象。

## 5. 明确不做

登录、钱包连接、余额扫描、社区、聊天、AI 输入框、广告位、评分/用户数/合作 logo。
